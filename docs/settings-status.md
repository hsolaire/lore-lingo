## 配置持久化（2026-10-11）

- `TranslationConfigService` 统一读取与保存现有 `sys_model_profiles`、`sys_translation_settings`；两张表在同一事务提交，保留未编辑的翻译行为和模型选项，无需新迁移。
- Tauri 读写命令在阻塞工作线程调用存储，设置存储单独串行访问，不占用捕获服务锁。启动快照与下一次捕获读取同一个持久化默认模型。
- 密钥只存入原生系统存储，SQLite 只有随机 `secret_ref`。密钥替换先写新条目并验证可读，再切换数据库引用；失败保留旧配置，提交后尽力清理无人引用的旧条目。崩溃或清理失败可能留下不再引用的系统条目，不会将已提交配置误报为失败。
- 缺失的系统凭据保留地址和模型，密钥字段留空以便重新填写；凭据访问被拒绝或数据库读取失败时显示读取失败并禁用保存。不降级为明文文件或浏览器存储。
- API Key 仍只在必要的运行期配置 DTO、密码输入框和请求内存中使用，调试输出遮盖密钥。保存不验证网络、模型或鉴权。
- 工具栏临时语言切换仍属于当前会话；OCR 预设、快捷键录入等未接入的设置不在本次持久化范围内。
- 完整前端测试 75 项通过，生产构建通过；Rust 常规测试 43 项通过，默认忽略 Vision 与两项原生凭据测试。真实 macOS 钥匙串跨独立进程恢复另行运行通过，并清理隔离数据库和临时凭据；Windows 原生验证尚未执行。

## 集中配置目录（2026-10-12）

- 默认数据库统一为 `~/.lore-lingo/lore-lingo.sqlite3`，Windows 使用用户主目录下的同名 `.lore-lingo` 目录；不随应用标识或启动工作目录变化。
- 目标库不存在时，从旧 Tauri 应用数据目录生成 SQLite 一致快照迁入，包含 WAL 中已提交的数据；原库保留，已有目标库不覆盖。密钥引用保持不变，不读取或迁移系统密钥本体。
- 迁入先校验临时快照，再发布到最终位置；失败不发布空库、不回退旧位置，修复后可以重试。新建 Unix 目录／数据库权限分别为 `0700`／`0600`。
- 隔离测试覆盖首次启动、重复启动、WAL、既有目标优先、损坏库、未来模式版本、目标不可用和 Unix 权限。Windows 原生目录与文件系统行为仍待验证。
- 本轮完整检查：前端 75 项、Rust 常规 50 项通过，构建、格式、编译、Clippy 通过；本机实际通过同一 Rust 存储入口完成旧库迁入，完整性检查通过，原库文件保持不变。
