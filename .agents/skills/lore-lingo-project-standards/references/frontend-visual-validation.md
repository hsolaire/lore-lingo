# 前端视觉与交互验收

## 验收矩阵

- 分别在 macOS WKWebView 和 Windows WebView2 上验收，不用一个平台的浏览器截图代替另一个平台。
- 覆盖浅色、深色、增加对比度、减少透明度和减少动画。
- macOS 覆盖 Retina、外接普通 DPI 和显示器切换；Windows 覆盖 100%、125%、150%、175% 和 200% DPI。
- 主窗口至少覆盖配置的默认尺寸与最小尺寸；悬浮字幕覆盖短文本、长文本、换行、控制条展开和显示器恢复。
- 覆盖加载、空、权限拒绝、能力不可用、错误、重试和成功状态。

## 自动检查

- 运行 `pnpm build`；存在 lint、unit 或 component scripts 时同时运行相应检查。
- 为选择器、对话框、抽屉、下拉菜单、开关和悬浮字幕控制条测试键盘路径与焦点恢复。
- 测试平台主题选择、系统明暗变化、减少动画和材质降级；平台判断必须来自能力测试夹具。
- 检查无障碍名称、实时区域、对比度和颜色以外的状态信号。
- 不因测试环境缺少原生材质而伪造成功；使用显式测试夹具区分“支持”“不支持”和“失败”状态。

## 截图检查

- 使用可用的浏览器自动化检查布局、文字溢出、弹层定位、z-index、焦点和响应式尺寸。
- 对主窗口和悬浮字幕分别截图；两个入口必须加载相同的语义 token 和正确的平台覆盖。
- 检查没有水平滚动、不可解释空白、嵌套卡片、控件跳动、文字遮挡和透明区域拦截输入。
- 检查所有图标来自 Lucide，同类图标尺寸一致，图标按钮有工具提示。
- 视觉差异只能证明渲染变化受控，不能证明原生材质、窗口层级、拖拽和 DPI 行为正确。

## 原生烟雾测试

- macOS 验证真实 Liquid Glass 和活力材质、交通灯、标题栏拖拽、减少透明度和不透明降级。
- Windows 验证 Mica/Acrylic、标题栏按钮、DPI 切换、Windows 10 降级和高对比度。
- 两个平台都验证悬浮字幕置顶、自身捕获排除、内容尺寸、移动、关闭和显示器断开恢复。
- 记录实际操作系统、WebView 版本、缩放、显示器拓扑和未支持能力；不得只写“跨平台通过”。

## 完成条件

- 界面在所有目标状态下可读、可操作且无重叠。
- 平台外观由主题与原生适配器共同实现，业务组件不存在用户代理分支或原生句柄。
- 原生效果不可用时，降级表面仍满足对比度、焦点和输入边界要求。
- 产品文案统一使用“悬浮字幕”，新代码统一使用 `Subtitle` / `subtitle` 前缀。
