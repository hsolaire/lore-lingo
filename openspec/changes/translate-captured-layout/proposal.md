## Why

LoreLingo 当前的区域选择、OCR 设置和翻译内容都是相互独立的界面模拟，无法把一次截图转换为可翻译且保留原始排版的结果。用户需要在完成区域截图后直接得到按原位置呈现的译文，而不是一段失去段落、列表和表格关系的纯文本。

## What Changes

- 新增截图翻译任务，将一次已完成的区域截图依次交给 OCR、布局整理和翻译服务。
- 新增稳定的 `LayoutDocument` 契约，保存图像尺寸、文本块 ID、块类型、阅读顺序、归一化边界框、原文、译文和置信度。
- 新增可替换的 OCR 与翻译后端边界；第一版在 macOS 使用系统 Vision OCR，并通过用户显式提供的 OpenAI 兼容配置执行翻译。
- 新增截图翻译结果视图，以原截图为背景并按文本块位置覆盖原文、译文或双语内容。
- 新增加载、无文字、权限/能力不可用、翻译配置缺失、后端失败和重试状态。
- 移除翻译设置中的真实密钥外观默认值；用户显式保存后，非密钥配置与凭据引用写入现有 SQLite 表，密钥本体由系统凭据存储保管；默认数据库集中在 `~/.lore-lingo`，兼容旧目录安全迁入。

## Capabilities

### New Capabilities

- `captured-layout-translation`: 定义截图 OCR、结构化文本块、保序翻译、布局覆盖渲染和失败恢复行为。

### Modified Capabilities

无。

## Impact

- 前端新增 `src/types/`、`src/services/`、截图翻译状态编排和主窗口结果组件。
- Rust 新增截图翻译领域模型、服务、命令以及目标限定的 macOS Vision 适配器。
- Tauri IPC 新增单次截图翻译命令和稳定结构化错误，不暴露系统句柄、原生框架对象或本地路径。
- OpenAI 兼容翻译需要运行时网络连接和用户显式输入的 endpoint、模型及 API key；捕获内容不会被持久化。
- Windows 真实 OCR 在本变更第一阶段报告为不支持，不模拟成功；共享契约为后续 Windows OCR 适配器保留边界。
